# Architecture

Feature-based structure adapted from the team's React project (Pegaxus) to the Next.js App Router:
routing lives in `app/`, each section is a self-contained feature, and UI components never fetch.

## Folder structure

```
src/
├─ app/                        Routing only: layouts, pages, metadata, composition
│  ├─ [locale]/                layout.tsx (root <html>), page.tsx (home), template.tsx (transition)
│  │  ├─ projects/[slug]/      case-study pages
│  │  ├─ not-found.tsx, opengraph-image.tsx
│  ├─ api/github/recent/       route handler used by the client-side activity list
│  ├─ sitemap.ts, robots.ts, icon.svg
├─ features/                   One folder per page section
│  ├─ hero/ about/ tech-stack/ projects/ github-activity/ contact/ references/
│  │  ├─ components/           pure UI (props in, JSX out)
│  │  ├─ services/             data mapping (GitHub data → view models), no React
│  │  ├─ hooks/                client logic (e.g. React Query)
│  │  ├─ types/ constants/
│  │  └─ index.ts              public API — import a feature only through this file
├─ shared/
│  ├─ components/ui/           Section, Figure, Cite, ButtonLink, Tag, Reveal, BrandIcon…
│  ├─ components/layout/       SiteHeader, SiteFooter, ThemeToggle, LocaleSwitcher, MobileNav
│  ├─ components/three/        Fig. 1: lazy WebGL terrain + static SVG fallback
│  ├─ lib/github/              GitHub client, Zod schemas, cached service, snapshot loader
│  ├─ lib/tech-catalog.ts      dependency name → label + layer
│  ├─ hooks/ utils/ constants/
├─ providers/                  ThemeProvider, QueryProvider, AppProviders (client)
├─ config/                     site, featured projects, references, env (Zod, server-only)
├─ i18n/                       routing, navigation, request config, messages/{en,vi}.json
├─ data/github-snapshot.json   generated by scripts/sync-github.ts (committed)
├─ styles/globals.css          design tokens (light/dark), fluid type scale
└─ proxy.ts                    next-intl locale routing (Next 16 "proxy", formerly middleware)
```

### Rules

- **Server Components by default.** `"use client"` only for interactivity, animation and 3D:
  theme/locale toggles, mobile menu, `Reveal`, `PageTransition`, the WebGL figure, recent activity.
- **No fetching in components.** Pages call `getGitHubData()`, pass the result through feature
  `services/` and hand plain props to components.
- **Feature boundaries.** Features import from `shared/`, `config/`, `i18n/` and their own folder —
  never from another feature. Anything two features need moves to `shared/`
  (e.g. `tech-catalog.ts` is used by both tech-stack and projects).
- **No hard-coded copy.** All UI text is in `src/i18n/messages/*.json`; message keys are
  type-checked (`src/i18n/next-intl.d.ts`). Project slugs are typed from the message keys, so a
  project without copy fails to compile.
- **Responsive without pixels.** Tailwind scale, `%`, `rem`, `aspect-*`, `max-w-*` and `clamp()`
  tokens only. `grep -rE '\[[0-9.]+px\]' src` must return nothing. The only pixel values are in
  `opengraph-image.tsx`, which renders a fixed-size bitmap.

## Data flow

```
GitHub GraphQL + REST
      │  fetchGitHubData()  (shared/lib/github/fetch-github-data.ts — plain TS, Zod-validated)
      ├──────────────► scripts/sync-github.ts ──► src/data/github-snapshot.json (committed)
      ▼
getGitHubData()  (github.service.ts, server-only)
  'use cache' · cacheLife('hours') · cacheTag('github')
  no token / API error ──► snapshot
      ▼
app/[locale]/page.tsx ──► feature services (getProjects, deriveTechStack, getActivitySummary…)
      ▼
feature components (props only)
```

- One GraphQL request fetches the profile, the 12-month contribution calendar and, per featured
  repository, languages, dependency manifests (`package.json` / `pom.xml`), the author's commit
  count on the default branch and PR counts. The public email comes from REST `GET /users/{login}`
  because GraphQL requires an extra token scope for it.
- **Revalidation:** pages are prerendered at build time and refreshed at most once an hour
  (shown as `Revalidate 1h` in the build output). `revalidateTag('github')` refreshes on demand.
- **Client-side data:** only "Latest public activity" uses TanStack Query, through
  `/api/github/recent` (cached for minutes) so the token never reaches the browser.

## Adding a featured project

1. Add an entry to `src/config/featured-projects.config.ts` (`repo`, `manifests`, `context`,
   `references`).
2. Add copy under `projects.items.<slug>` in **both** `en.json` and `vi.json` — only facts the
   repository's README or code supports.
3. Add a source to `src/config/references.config.ts` if the project needs its own citation.
4. Run `npm run sync:github` to refresh the snapshot, then `npm run build`.

## Adding a section

1. Create `src/features/<name>/` with `components/`, optional `services/`, and an `index.ts`.
2. Build the UI with `Section` (gives the number, title, rail layout and anchor id).
3. Add the anchor to `SECTIONS` in `shared/constants/sections.ts` (navigation and numbering) and
   a label under `nav` / `sections` in both message files.
4. Compose it in `app/[locale]/page.tsx`, passing data from a service.

## Design tokens

`src/styles/globals.css` defines colour tokens for light (`:root`) and dark (`.dark`, toggled by
next-themes) and exposes them to Tailwind via `@theme inline` (`bg-paper`, `text-ink`,
`text-accent`, `bg-accent-decor`…). Text accent is `#A04D6E` on white (5.55:1) and `#E8A0BF` on
black (10.2:1); `#E8A0BF` is never used for text on white (2.06:1). Type uses Newsreader (display),
Be Vietnam Pro (body) and JetBrains Mono (labels), all with Vietnamese subsets via `next/font`.
